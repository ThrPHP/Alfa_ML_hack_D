# Где первая сессия теряла время и контекст — и как не наступить снова

## Контекст (токены)
| что съело | как избежать |
|---|---|
| PDF кейса (20 страниц, читается картинками, ~7 МБ) — два чтения по 10 страниц | **Не читать PDF.** Всё нужное — в `case.md`. Открывать только конкретную страницу, если вопрос не покрыт |
| `cat` всех модулей ml_core (~40 КБ) и `docs/CONTRACTS.md` (~33 КБ) целиком; вывод не влез и ушёл в отдельный файл, который пришлось дочитывать | Сначала `architecture.md`; потом `grep -n "^def \|^class "` по нужному модулю и `Read` с offset/limit только нужной функции |
| Длинные логи прогонов агента в выводе | Фильтровать: `grep -E "(->|run «|refit|done|skipped|ERROR)" log \| sed -E 's/\{"model_name.*//'` |
| Объяснения вариантов архитектуры «по-инженерному» — пользователь не понял, пришлось переспрашивать | Пользователю объяснять просто, по-русски, с примером; варианты — коротко и с рекомендацией |

## Время
| что съело | сколько | как избежать |
|---|---|---|
| Тесты параллельно с прогоном агента на реальных данных (4 ядра, OpenMP-переподписка) | замедление в 2–3 раза: LightGBM-фолд 155 с вместо ~60, полный набор тестов 6 мин вместо 2; искажённые замеры заставили агента досрочно остановиться | **Никогда не запускать тесты и прогоны агента одновременно.** Замеры времени — только на «тихой» машине |
| Полный набор тестов | ~2 мин (3 e2e-теста в `tests/test_agent_research.py` — ~1.5 мин) | В цикле правок: `pytest tests/ -q -p no:warnings --deselect tests/test_agent_research.py` (**~25 с**); полный — перед коммитом |
| Прогон агента на классификации | 10–15 мин; LightGBM-мультикласс ~60–150 с/фолд, CatBoost-мультикласс ~150 с/фолд, refit ~25–50 с | Быстрые проверки — на **регрессии** (`--budget-s 300`, ~2 мин, фолд ~2–17 с). Классификацию — только когда нужна именно она, в фоне (`run_in_background`) |
| Ожидание фонового прогона через `until ! pgrep -f run_agent_local` — команда находила **саму себя**, не завершилась, висела 25 мин до таймаута | 2 × 25 мин | Не ждать через `pgrep -f <шаблон>`. Запускать сам прогон с `run_in_background` и ждать его уведомления; или ждать по PID: `while kill -0 $PID 2>/dev/null; do sleep 5; done` |
| Установка окружения: системный Python 3.13, нужен 3.12 | ~1 мин | Команда в `CLAUDE.md` (uv ставит 3.12 сам). Полный `Base/requirements.txt` (torch, autogluon) не ставить — не нужен |
| Отладка XGBoost (RMSE 115–236) | ~5 мин | Уже разобрано: категориальные разбиения переобучаются, лечится `max_cat_threshold=32` (в playbook есть) |

## Логические ловушки, на которые уже наступали
- Оценка «скошен ли таргет»: условие `mean > 1.1·median` пропустило реальный длинный хвост (skew 4.8). Сейчас `max > mean + 4·std` **или** `mean > 1.05·median`.
- «Больше деревьев» на регрессии хуже: сдвиг между годами (`Year_Factor`), выигрывает регуляризация. Не делать вывод «мало обучилось» по одному конфигу.
- `ml_core.validation` `time_split` с `n_splits>1` кладёт более поздние периоды в train фолда — поэтому агент использует 1 фолд.
- Тесты, проверяющие точный набор `source` в журнале, ломаются при добавлении новых фаз (так было с local-search) — проверять подмножество.
- Persisted-output: если вывод команды >~30 КБ, он уходит в файл и требует второго чтения — сразу ограничивать вывод (`head`, `grep`, `sed -n`).
